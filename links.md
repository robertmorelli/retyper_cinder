# Links the graph makes

- edge from an annotation's type to the type of every expression the type checker says it reaches
- edge from an annotation's type to the type context of every expression the type checker says it constrains
- union of every annotation the type checker reports in the same component
- edge from the type of `T` in `x: T = v` to the type context of `v`, whether `x` is a name or an attribute
- edge from the type of `it` in `for t in it` to the type of `t`, when `t` is a plain name
- union of the annotation on `t` and the annotation on `it` in `for t in it`, when `t` is a plain name
- union of a loop's annotation and what it walks over, held over until the annotation is reached when it appears later in the file
- edge from the type of `o` to the type of `o.a`
- edge from the type of `o` to the type context of the value stored in `o.a = v`
- edge from the type of `c` to the type of `c[i]`
- edge from the type of `c` to the type context of `i` in `c[i]`
- edge from the type of `c` to the type context of each of `a`, `b`, `s` in `c[a:b:s]`
- edge from the type of `c` to the type context of the value stored in `c[i] = v`
- edge from the type of `l` to the type context of `r` in `l + r`, and from the type of `r` to the type context of `l`
- edge from the type of each side of `a < b < c` to the type context of every other side
- edge from the type of `f` to the type context of every argument in `f(a)`
- edge from the type of `f` to the type of the result of `f(a)`
- edge from the type of a parameter to the type context of the matching argument, when the name resolves to exactly one `def` or one class with an `__init__`
- `o.a`, `c[i]`, and `f(a)` carry the annotation of whatever they were read off, so later edges can start from it
- `box(x)`, `int64(x)`, `Array[T](x)` and friends carry their arguments' annotations, so later edges can start from them
- a name used inside a loop body carries the annotation of what the loop walks over
